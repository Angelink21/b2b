# Старт: сайт Fagor Professional через Cursor

Этот набор превращает прототип в настоящий сайт на Next.js. Агент Cursor работает по этапам, каждый этап заканчивается проверкой.

## 1. Один раз подготовьте компьютер
1. Установите Node.js 22 LTS (подойдёт и 24 LTS), Git и Cursor.
2. В терминале выполните `corepack enable`, чтобы появился pnpm.
3. Создайте папку проекта, например `fagor-site`, откройте её в Cursor и выполните `git init`.

## 2. Куда положить файлы
Распакуйте архив в корень папки проекта, чтобы получилось так:

```
fagor-site/
├─ AGENTS.md                 ← Cursor читает автоматически
├─ .cursor/rules/*.mdc       ← правила, Cursor читает автоматически (папка скрытая)
├─ docs/
│  ├─ PROMPTS.md             ← все этапы с готовыми промптами
│  ├─ DESIGN.md              ← дизайн-система
│  ├─ DATA_CONTRACT.md       ← как читать таблицу моделей
│  ├─ ACCEPTANCE.md          ← критерии готовности
│  ├─ DECISIONS.md           ← журнал решений (ведёт агент)
│  └─ prototype.html         ← эталон вида и поведения
└─ data/products_clean.csv   ← ваша таблица моделей
```
Скрытые папки: на Mac Cmd+Shift+. в Finder, на Windows «Показать скрытые элементы».

## 3. Как работать (шесть правил)
1. Один этап = один новый чат. Так агент не путается в длинном контексте.
2. На этапах 0, 2, 4, 7 включайте Plan Mode (Shift+Tab в поле ввода): агент сначала покажет план, вы подтвердите.
3. Команда для запуска этапа: `Выполни ЭТАП N из @docs/PROMPTS.md`. Подставьте номер.
4. После каждого этапа смотрите результат в браузере (`pnpm dev`) и делайте коммит. Если этап пошёл не так, откатите `git restore .` и повторите.
5. Для ревью открывайте новый чат (лучше с другой моделью) и вставляйте промпт R1 из `docs/PROMPTS.md`.
6. Если агент повторяет одну и ту же ошибку, запустите промпт R5: он предложит правку в правилах, чтобы ошибка не вернулась.

## 4. Порядок этапов
0 Разведка и план · 1 Каркас и токены · 2 Данные каталога · 3 UI-кит · 4 Главная · 5 Каталог и карточка ·
6 Сравнение и datasheet · 7 Заявки КП · 8 Движение · 9 SEO · 10 Качество · 11 Деплой и передача · 12 Фото и CMS (когда будут фото).

## 5. Что нужно от вас (агент задаст эти вопросы на этапе 0)
- Куда присылать заявки: email, Telegram, CRM?
- Где будут жить фото: хранилище/CDN, CMS или ссылки в таблице?
- Что означают диапазоны вроде `8-9` в колонке «Завантаження (кг)»?
- Что означают суффиксы в названиях (E, G, S, HW, V, P, XP, R…)?
- Логотип, фирменный цвет, контакты, адрес, юридический текст политики конфиденциальности.
- Кто переводит описания на английский (в таблице они только украинские)?
- Домен и хостинг (рекомендация: Vercel).
